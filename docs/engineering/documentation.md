# 文档治理规则

> 状态：已采用

## 1. 文档分层

| 目录 | 作用 | 是否当前事实源 |
| --- | --- | --- |
| `docs/architecture/architecture.md` | 全局架构 | 是 |
| `docs/architecture/adr/` | 长期架构决策 | Accepted ADR 是 |
| `docs/sdd/features/<feature>/` | 单项功能当前规格 | 是 |
| `docs/planning/` | 跨功能路线图与计划索引 | 项目计划入口 |
| `docs/deliverables/<feature>/` | 阶段评审快照 | 否，记录当时事实 |
| `docs/quality/` | 测试、回归与版本验收 | 测试方法与执行证据 |
| `docs/benchmarks/` | 平台特征评测 | 评测方法、基线与报告事实源 |
| `docs/deploy/` | 开发、部署、监控、回滚操作 | 操作事实源 |
| `docs/releases/` | 发布内容与限制 | 对应版本事实源 |
| `docs/archive/` | 历史资料 | 否 |

## 2. 必要元数据

规格文档至少包含状态、规格版本、更新日期和关联文档；阶段报告至少包含时间、评审对象、对应提交/规格版本、结论和未完成项。

推荐状态集合：`草案`、`待评审`、`已接受`、`实施中`、`已实现`、`已验证`、`已废弃`、`已替代`。状态必须描述文档或功能的真实阶段，不以文件存在代替评审、实现或验证。

## 3. 修改规则

- 当前行为只在 SDD 定义；README 只作入口和概览；
- ADR 记录“为什么”，不复制完整功能规格；
- Deliverable 记录“当时评审了什么”，原则上不随当前设计改写；
- 文档迁移时旧路径保留导航页，直至引用全部更新；
- 删除前检查仓库内链接；
- 不允许两份文档同时维护同一任务状态；任务当前状态以功能 `status.md` 或外部工单系统为准。
- 文件移动必须同步文档中心、VitePress 导航、README、AGENTS 和包发布清单中的路径；
- 文档应链接事实源，不复制会频繁变化的状态、命令结果或配置清单。

## 4. 功能规格包最低组成

`README`、requirements、architecture、contracts、必要时 UI、state-machine、plan、tasks、test-spec、traceability、status。简单功能可以合并文件，但不能丢失对应语义。

## 5. 变更记录

破坏性契约、需求范围、状态机和安全边界变化必须增加版本或变更记录，并重新评估关联任务、测试和阶段结论。

## 6. 文档站验证

文档目录、链接、导航或 VitePress 配置变化后必须运行 `pnpm docs:build`。静态站构建成功不代表文档内容已经通过业务评审，两种状态必须分开记录。

## 7. 归档与删除

- 仍有审计价值但已被替代的文档进入 `docs/archive/`，并标注替代入口和归档日期；
- 临时草稿若未形成决策、没有外部引用且不具备追溯价值，可以删除；
- 已接受 ADR、阶段 Deliverable 和发布记录不得通过覆盖历史来“保持最新”；
- 归档文件不得继续承载当前任务状态或新增设计。
