# 数据能力平台与任务闭环

## 决策

Workmate 采用“数据工作台、数据网关、任务/Skill”三层模型。

- **数据工作台**是数据控制中心：维护连接、发现元数据、补充业务标注、发布应用数据单元。
- **数据网关**是唯一运行时入口：执行 `options`、`query`、`aggregate`、`write`，统一注入当前登录用户上下文，并记录审计。
- **任务模板与 Skill**只声明需要的应用数据单元和业务结果，不直接连接数据库，不保存凭据。

## 核心对象

### 应用数据单元

应用数据单元是面向任务和应用的数据契约，不是物理表的别名。当前数据对象第一期维护数据集的最新 Schema、业务说明与连接说明，**暂不实现数据 Schema 版本和兼容性管理**。更完整的操作输入、结果结构和写入策略仍按下面的平台目标逐步建设，不代表已经上线。

### 操作 Spec

操作 Spec 是网关可识别、可测试的稳定动作，例如“搜索客户”“查询项目订单”“写入经营结果”。它声明输入、输出、数据集、权限要求、分页、是否有副作用和版本。Spec 是底层能力；Skill 可以组合多个 Spec，描述专业做法。

### Skill

Skill 负责专业流程、业务判断、计算和报告生成。Skill 只能调用已发布的网关操作，不能直连数据库或接收前端伪造的用户身份。

## 用户流程

普通用户只看到：

```text
选择任务 → 选择/搜索业务数据 → 填写参数 → 运行 → 查看结果
```

数据管理员看到：

```text
连接数据源 → 读取元数据 → 补充字段标注 → 生成操作草稿 → 沙箱测试 → 发布数据单元
```

元数据自动生成候选字段类型、主键、关联关系、可搜索字段和输入选项。业务口径、敏感级别、写入方式等必须人工确认后发布。AI 可以提出标注建议，但不能把建议直接变成生产规则。

## 访问与权限的简化规则

第一阶段不建设独立策略语言。所有数据网关调用自动取得当前会话的 `orgId`、`userId`、`role`，数据工作台连接和数据集先做所属权校验，网关再执行数据集范围过滤。前端和模型提交的 userId、orgId、SQL、连接凭据均不可信。

任务只引用已发布的数据单元。查询选项和正式取数使用同一个网关，但分为 `options` 和 `query` 操作；选项只返回 ID、显示名和必要辅助字段，正式运行时再次验证所选 ID。结果集默认继承任务与输入数据的可见范围。

手动运行使用当前登录用户；定时运行暂使用任务所有者，所有者失效时任务暂停并提示重新授权。未来需要服务账号时再增加，不把它提前引入当前版本。

## 数据交换与写入

任务结果使用“统一数据交换信封＋目标 Schema”，而不是自由 JSON：

```json
{
  "dataset": { "id": "business-results", "schemaVersion": "1.0" },
  "operation": "append",
  "run": { "taskId": "task_1", "runId": "run_1" },
  "records": [],
  "metadata": { "currency": "CNY" }
}
```

网关写入负责 Schema 校验、类型/单位转换、主键策略、追加或更新、幂等和回执。外部应用使用字段映射适配器，不让每个 Skill 编写一套入库 API。

## 发布生命周期

```text
元数据草稿 → 操作 Spec 草稿 → 沙箱测试 → 人工确认 → 发布版本 → 被任务/Skill/应用使用
```

上述操作发布生命周期是后续平台目标。数据对象第一期每次保存直接更新当前 Schema，无发布版本、固定旧 Schema、历史回放或兼容性检查。字段 ID 不允许通过标注编辑变更；API 同步按源字段匹配保留 ID 与标注，只是避免重建丢失，不提供结构变化兼容承诺。任务结果契约版本与应用 HTML 修订是独立机制，不受此次范围调整影响。

## 当前闭环

当前试验版已在数据网关中提供基于数据工作台数据表的：

- 数据单元元数据读取。
- 当前用户所属数据源/数据表校验。
- `options`：按字段搜索并返回 `value / label / description`。
- `query`：按字段过滤、分页读取结构化数据。
- 数据对象说明、连接说明、表说明、字段含义/单位/枚举/敏感标识编辑。
- API URL 与入参/返参标注，JSON 对象/对象数组文件导入。
- `GET /data/gateway/schema`：所属权校验后的最新模型可读 Schema，不含连接密钥和记录样例。
- 应用创建/优化从同一 Schema 组装模块读取说明；API 同步保留已有表 ID、匹配字段标注。
- 新定制应用显式等待页面绑定，绑定后才标记定制交付；不会把模板回退页当作 AI 成果。交付工具与真实 HTTP 取数已做隔离集成验证，真模型端到端验收状态见 [数据应用交付闭环](../sdd/features/data-app-closure-v1/status.md)。

具体范围与验证见 [数据对象工作台第一期](../sdd/features/data-objects-v1/README.md) 与 [远端数据库接入](../sdd/features/remote-database-v1/README.md)。MySQL/PostgreSQL 已提供管理员只读连接、选库选表、本地快照导入与固定目标刷新；连接密码仅本次请求使用，不持久化。SQL 驱动仅在 API 内部适配层，元数据查询参数化，选表名称按驱动引用且与发现列表核对，使用 READ ONLY 事务。前端/应用仍通过已有网关查询快照，不传原库凭据或任意 SQL；原库写入、跨源联查、操作发布、AI 自动补注未实现。API 也是显式同步到本地后查询，不是任意远端请求代理。

下一步将把内置经营汇总任务的输入字段接到该网关，验证“数据表 → 选项/查询 → Skill → 结果数据集/报告”。

## 非目标

当前不支持任意上传可执行代码、任意 SQL、复杂企业级 ABAC、跨组织共享、服务账号代理和自动猜测业务指标口径。它们等真实数据单元和用户流程验证后再逐步增加。


## 当前统一访问边界

任务和数据应用均通过数据工作台所属的数据访问边界执行：先按当前用户、组织和数据表所有权校验，再查询数据。网关单元返回字段 Schema、可用操作和 `owner-scoped` 访问模式；页面只获得业务数据，不接触数据库凭据。当前任务闭环中的客户选项和应用查询已经使用网关查询模型，后续聚合、写入和外部连接器也必须注册为网关操作，禁止业务模块自行拼接 SQL。
