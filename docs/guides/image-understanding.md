# 图片理解：主模型直读或应用模型定向识图

## 使用

1. 重新构建并启动包含 VIS-001 的应用/API。
2. 设置 → 模型，在确实支持图片输入的**对话模型**下勾选“支持图片理解”，保存配置。它不是“图片生成”模型类型，也不会自动替换当前主模型。
3. 选用该模型（注意员工的默认模型覆盖），把员工执行引擎设为 Pi，关闭自动调度、移除协作者。
4. 对话中点击“添加图片”，或粘贴剪贴板图片，填写问题后发送。上传完成会显示编号和缩略图，可移除、点击查看原图。
5. 在同一对话继续问图片细节，不必重复上传。模型每轮接收最近4张原图；更早图片请重新上传。

PNG/JPEG/WebP，每张最多10 MB，每次最多4张。建议先用一张清晰、非敏感的截图测试。模型的实际图像尺寸/内容限制仍以服务方为准。

## 主模型不能看图时（M2）

1. 设置 → 模型 → 添加模型，复用已有 Provider 连接，类型选择 **图片理解**，输入确实支持图片输入的视觉模型 ID。
2. 将该模型设为默认“图片理解”模型；它不会替换默认对话模型。
3. 数字员工 → 员工设置 → 应用模型能力，把“图片理解”从关闭改为按需使用（或优先使用）。保持单员工 Pi 对话。
4. 使用原有纯文本主模型上传图片并提问。输入框会告知识图服务与模型；执行过程显示图片理解活动和进度。
5. 工具自动携带用户原始问题、必要历史上下文以及模型补充的关注点；如问“连接为什么失败”，识图围绕报错、地址、状态码等内容，不只泛泛描述画面。

追问新细节时可重新读取最近4张原图。相同Run的相同问题/图片/关注点复用结果，最多3种识图请求；相同失败不自动反复请求。跨轮不复用旧分析来冒充重新看图。

主模型具备视觉声明时优先直接看图，不重复调用识图应用模型。未绑定模型或员工未授权时，纯文本主模型不能上传图片，会有配置提示。

## 数据与失败说明

图片先保存在本地会话附件目录；发送时根据配置由主模型或图片理解应用模型服务处理。后者还会收到用户问题和最近必要文字上下文，主模型收到文字识图结果，不收到图片内容块。与模型服务共享前，请确认图片和上下文不含不应外发的个人或业务敏感信息。会话/Run 中保存引用而非 Base64，删除会话会清理其图片；移除待发送附件不立即删除本地副本，随会话删除清理。

不支持的模型/引擎会明确拒绝，不会静默改用其他模型。图片丢失或引用不属于当前会话时要求重新上传。含图会话改用纯文本模型且没有授权图片理解应用模型时，应先配置并开启该能力、切回视觉模型，或新建纯文本会话。

当前已验证两条工程链路与本地 mock；真实模型输出质量需按实际配置验收。DSH/AgentScope、PDF/视频和多员工协作仍不在本轮范围。工具调用需要主模型具备可靠的工具使用能力；这是模型调用机制，不保证模型永不遗漏调用或产生错误推断。
