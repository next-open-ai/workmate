# AMC-UX-USAGE-001 · 多模态输入与应用模型用量

> 状态：已实现并完成工程验收 · 2026-09-25

## 需求

- UX-01：图片、录音作为输入附件能力，位于输入框底部左侧工具栏；使用统一尺寸的图标按钮，不以常驻长文案挤占编辑空间。
- UX-02：能力说明、限制和不可用原因在键盘聚焦或鼠标悬浮时显示；按钮保留可访问名称，已选附件以可移除卡片展示。
- UX-03：执行选项、模型选择和发送操作与附件入口分组，在窄屏允许换行且发送键保持右侧。
- USAGE-01：所有返回Token用量的应用模型调用均产生归一化`run.usage`事件，并标记实际Provider、模型和能力；缓存复用不重复计量。
- USAGE-02：运行总量包含主模型及应用模型；“按模型”统计必须按每次调用的实际模型归属，不能把应用模型Token计入主模型或用应用模型覆盖运行主模型。
- USAGE-03：不返回Token的图片生成、ASR、TTS等协议不得估算或虚构；后续厂商提供usage时可复用同一归一化入口。

## 任务与测试

- UXU-01：重排聊天输入框、悬浮提示、附件卡片及响应式布局。
- UXU-02：扩展用量步骤归属契约、应用模型usage归一化与事件发送。
- UXU-03：补齐agent-core/orchestrator单元测试，执行类型、构建、文档和浏览器验收。

验证覆盖：Pi/OpenAI两种usage字段、视觉缓存不重复统计、主模型与应用模型同Run分别按模型聚合、旧Run步骤兼容、禁用状态提示、图片/录音附件移除和窄屏换行。

## 兼容与边界

新增字段均为可选，不迁移旧数据；旧usage步骤继续归属于Run主模型。关闭员工应用能力即可回滚运行行为，输入框仅为展示调整。成本统计不在本阶段范围内。

## 过程与证据

- UXU-01完成：图片/录音合并为输入框左下附件组；说明仅在hover或键盘focus显示；附件卡片、移除、禁用原因及工具栏换行已实现。隔离浏览器验证输入布局、焦点提示和图片卡片通过。
- UXU-02完成：`run.usage`增加可选能力归属；Run保留主模型身份，`usage.byModel`持久化主模型/应用模型独立累计；设置→用量按模型显示“主模型”或“应用模型 · 能力”。视觉缓存结果不重复计量；无usage的协议不估算。
- UXU-03完成：contracts、agent-core、orchestrator及renderer类型检查通过；agent-core 111/111、orchestrator 42/42通过；API与Renderer构建通过；完整视觉HTTP回归通过。隔离界面验证同批两次运行：主模型60 Token、图片理解应用模型80 Token、总计140 Token，模型身份未互相覆盖。
- 验收期间识别并排除一次并行构建读取旧orchestrator产物的问题；最终证据使用依赖顺序`orchestrator → API`重建后取得。真实厂商是否返回usage仍取决于对应协议响应，未返回时不生成统计。
