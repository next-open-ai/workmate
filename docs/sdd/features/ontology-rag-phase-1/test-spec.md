# 测试规格

> 状态：实施中｜规格版本：0.1｜更新日期：2026-09-23

| ID | 场景 | 预期 |
| --- | --- | --- |
| ONT-TEST-01 | 写入后重新读取图谱 | 节点、关系和版本保持一致 |
| ONT-TEST-02 | 用别名查询实体 | 返回标准实体及扩展词 |
| ONT-TEST-03 | 查询有一跳关系的实体 | 返回关联节点和关系 |
| ONT-TEST-04 | 图谱为空或无匹配 | 策略为 `vector-only`，原向量检索正常 |
| ONT-TEST-05 | 图谱匹配且关联文档 | 原始与增强路径合并去重，提示文档合理加权 |
| ONT-TEST-06 | 首次打开含旧 JSON 的知识库 | 自动生成 `ontology.sqlite`，图谱、候选和审核状态保持一致，旧文件不删除 |
| ONT-TEST-07 | 发布及候选提交 | 节点、关系、候选状态与版本快照在同一事务中提交 |
| ONT-TEST-06 | archived 节点或关系 | 不进入查询计划 |
| ONT-TEST-07 | 非法 API 输入 | 返回 400 和契约错误，不写入文件 |
| ONT-TEST-08 | 无权限/过期/错误版本候选 | 在进入模型上下文前被硬过滤（P2） |
| ONT-TEST-09 | 模型返回实体与关系 JSON | 转换为符合契约的候选，证据中的 documentId/chunkId 必须来自本次选定切片 |
| ONT-TEST-10 | 模型返回代码围栏、额外文字或非法引用 | 可提取合法 JSON；非法候选被拒绝且不写入审核队列 |
| ONT-TEST-11 | 用户发起文档分析 | 生成候选后仍为 pending，只有人工接受并提交后才进入正式图谱 |
| ONT-TEST-12 | 13 个切片发起自动识别 | 按 4/4/4/1 分批，不截断任一源切片，最终候选合并后一次写入审核队列 |
| ONT-TEST-13 | 某批模型 JSON 被截断或格式错误 | 自动二分该批并重试；单切片仍失败时返回可理解的错误，不暴露底层 JSON 位置异常 |
| ONT-TEST-14 | 单个内容密集切片仍生成不完整 JSON | 仅在分析上下文中按自然边界继续缩小，候选证据仍引用原始 chunkId，知识库切片不被改写 |
| ONT-TEST-15 | 同一批包含可信证据和模型改写/编造的证据 | 丢弃证据不可核验的节点及依赖关系，可信节点继续进入人工审核区 |
| ONT-TEST-16 | 在本体检索验证区输入命中别名的问题 | 显示 `ontology-enhanced`、命中实体、关联节点、关系、扩展词和融合后的知识片段 |
| ONT-TEST-17 | 输入未命中正式本体的问题 | 显示普通向量召回及退化说明，原始向量结果仍可用 |
| ONT-TEST-18 | 正式本体为空、包含实体关系或超过 300 个实体 | 分别显示空态、可交互关系图或范围提示；搜索、布局切换、缩放和详情查看可用，候选数据不进入正式图谱视图 |
