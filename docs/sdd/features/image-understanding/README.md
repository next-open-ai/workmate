# VIS-001 · 图片理解（主模型直读 / 应用模型定向识图）

状态：M1 已实现并通过自动化及隔离界面验收，待真实 Provider 质量验收。目标：图片上传/粘贴 → 图文一起发送给主模型 → 回答 → 同会话追问原图。

M2：已实现文本主模型通过统一工具调用“图片理解”应用模型，自动附带原始问题和必要上下文；[M2规格、契约与测试](M2-application-vision.md) 是新增行为事实源。以下 M1 验收数据保留作阶段基线。

入口：[计划](plan.md) · [任务](tasks.md) · [状态](status.md) · [使用指南](../../../guides/image-understanding.md) · [测试报告](../../../quality/features/image-understanding/M1-report.md)。

## 需求与边界

- VIS-R1：单员工 Pi 对话，显式标记“支持图片理解”的对话模型直接接收图片；不增加图片生成 Provider，不进行先识图再摘要的二次模型调用。
- VIS-R2：JPEG/PNG/WebP，每张 ≤10 MiB，每次 ≤4 张；校验文件头，不接受 SVG、任意 URL、路径或内联图片 Prompt。上传失败可重试/移除，正在上传禁止发送。
- VIS-R3：附件使用结构化引用，服务端会话鉴权；原图落受控本机目录，会话持久化只存引用。发送即将图片交给所选主模型服务，界面提示此边界。
- VIS-R4：追问保留原图。滚动摘要不能代替原图；保留最近 4 张图片的原始关联问题，更多旧图可重新上传。会话删除清理其图片；未发送图片随会话删除清理。
- VIS-R5：主模型无视觉声明且无已授权图片理解应用模型、非 Pi 引擎、自动调度/协作者、旧无状态 chat 路径明确拒绝，禁止静默丢图或切模型。纯文本兼容。

不包含：OCR 专用模型、PDF/视频、IM 图片、批量图片、图片编辑、自动识别所有型号视觉能力。独立 vision Tool 已在 M2 补充，不属于 M1 原始范围。

## 契约与设计

contracts：`ChatImageAttachment { id: UUID, name, mimeType, size }`，消息可选 `attachments`（最多4张）。`ModelConfig.supportsVision?: boolean` 缺省 false。仅 user 消息允许图片。

API：鉴权后的 `/api/orch/sessions/:sessionId/images` POST 接收 `{name,dataBase64}`；GET `.../images/:imageId` 返回原图用于缩略预览。引用必须属于该 session。发送接口校验附件，执行前再次读取，失败返回明确错误。

`agent-core` 负责附件文件存取及 Pi ImageContent 转换；orchestrator 保存引用和最近图片追问上下文；API 负责 ownership；renderer 负责上传、预览、移除、配置及限制提示。主模型不会自行调用 Bash 下载/解析图片。

图片存储为本地持久化输入，不自动登记为生成资产。无 base64 进入会话/Run 记录。主模型一次最多接收最近4张图片，按历史顺序标注文件名；图片内容作为不可信用户数据，不作为系统指令。

## 兼容与回滚

配置 v3 增加可选字段，不自动猜测或修改现有模型。旧消息无附件继续有效。回滚前关闭支持图片理解；保留图片与引用，不破坏文字记录。移除功能后老版本仅能显示文字，不应继续含图会话而声称已看图。
