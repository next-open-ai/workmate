# MOBILE-FILE-001 · 手机对话传文件到电脑

状态：已实现，待真实手机与安装态验收。

## 需求

- MOBILE-FILE-R1：有效的手机对话二维码页面应提供简单、可发现的“传文件”入口，不影响正常对话。
- MOBILE-FILE-R2：上传沿用当前二维码会话令牌及资源归属校验；过期、越权或不存在的会话不得写文件。
- MOBILE-FILE-R3：文件优先保存到当前系统用户的 `Downloads`，不可写时回退 `Documents`。
- MOBILE-FILE-R4：文件仅落盘、不执行；安全化文件名，禁止路径逃逸，不覆盖同名文件。
- MOBILE-FILE-R5：单文件上限 20 MB；手机端展示选择状态、读取/上传进度、失败原因和最终相对位置。

## 交互

手机对话顶部提供“传文件”按钮。点击后展开内嵌面板：选择文件 → 显示名称与大小 → 上传到电脑 → 显示 `下载/文件名` 或 `文档/文件名`。上传成功后可继续选择其他文件。

## 安全与兼容

- 上传接口位于 `/api/chat-mobile/:token/upload`，不接受普通匿名请求，只接受尚未过期且仍能写入对应对话的 token。
- 服务端以独占创建方式写文件，发生重名时追加序号。
- 旧二维码页面无需新增数据迁移；服务重启并重新加载页面即可获得功能。

## 验收

- MOBILE-FILE-T1：API 与 Renderer 类型检查、构建通过。
- MOBILE-FILE-T2：无效 token 返回 410；无会话写权限返回 404。
- MOBILE-FILE-T3：空内容、非法 Base64 和超过 20 MB 的文件被拒绝。
- MOBILE-FILE-T4：重复文件名不会覆盖原文件。
- MOBILE-FILE-T5：真实手机在同一局域网完成上传并在系统下载/文档目录确认文件，列为安装态人工验收。
